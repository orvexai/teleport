# API Contracts

> **Quick orientation.** Teleport exposes its functionality through two complementary surfaces: **gRPC** (internal & SDK) and **HTTP REST + WebSockets** (browser & some clients). This document maps the surfaces and tells you where to look. Deep details (every service, every route, all middleware) are in [`findings/backend-api-surface.md`](./findings/backend-api-surface.md).

---

## 1. Two Surfaces

| Surface | Purpose | Defined in | Served by |
| --- | --- | --- | --- |
| **gRPC** | All authenticated machine-to-machine traffic — tsh, tctl, tbot, integrations, the operator, the Terraform provider, proxy-to-proxy peering, agents heartbeating to Auth. | `proto/teleport/` (internal) + `api/proto/teleport/` (public SDK) | `lib/auth/grpcserver.go` registers ~55 modern v1 services + the legacy `proto.AuthService`. |
| **HTTP REST + WebSockets** | Browser UI (`web/packages/teleport`), some `tsh` features that go through the proxy's HTTP listener, joining nodes (`/v1/scripts/node-join/install.sh`). | Routes registered programmatically on `httprouter.Router` in `lib/web/apiserver.go`. | `lib/web` + `lib/httplib` middleware. |

There is also a *third* surface: **ConnectRPC**, used **only** as a *client* to phone home to the prehog usage-telemetry endpoint (`buf-connect-go.gen.yaml` outputs in `gen/proto/go/prehog/`). It's not part of the public server surface.

## 2. gRPC — Public Go SDK Entry

The public Go SDK is the `github.com/gravitational/teleport/api` module:

```go
import "github.com/gravitational/teleport/api/client"

c, err := client.New(ctx, client.Config{
    Addrs: []string{"proxy.example.com:443"},
    Credentials: []client.Credentials{
        client.LoadIdentityFile("/path/to/identity"),
    },
})
```

`client.New(ctx, Config)` (`api/client/client.go:191`) tries up to 5 connection methods *in parallel* (first to succeed wins):

1. `authConnect` — direct to Auth.
2. `tunnelConnect` — through proxy's reverse tunnel.
3. `proxyConnect` — through proxy via SSH.
4. `tlsRoutingConnect` — through proxy via ALPN/TLS routing.
5. `tlsRoutingWithConnUpgradeConnect` — TLS routing with the ALPN connection-upgrade fallback (for HTTP/1.1-only load balancers).

**Credentials** (`api/client/credentials.go`):

| Constructor | When to use |
| --- | --- |
| `LoadTLS(*tls.Config)` | Raw TLS, direct-to-Auth only. |
| `LoadKeyPair(certFile, keyFile, caFile)` | Static cert/key/CA files. |
| `KeyPair(certPEM, keyPEM, caPEM)` | In-memory bytes. |
| `LoadIdentityFile(path)` | **Preferred for bots / integrations.** A `tctl auth sign --format=file` identity file. |
| `LoadIdentityFileFromString(content)` | Identity-file content as a string (for `$TELEPORT_IDENTITY` etc.). |
| `LoadProfile(dir, name)` | A `~/.tsh/` profile — also yields default addrs. |
| `NewDynamicIdentityFileCreds(path)` | Watches an identity file for refresh — **use this for tbot-renewed creds.** |

Each implements the `Credentials` interface (`api/client/credentials.go:46`): `TLSConfig`, `SSHClientConfig`, `Expiry`.

## 3. gRPC — Proto Tree Layout

Two parallel proto trees, one published, one internal:

| Tree | Purpose | Go output |
| --- | --- | --- |
| `api/proto/teleport/` | Public, re-published in the SDK. Stable surface. | `api/gen/proto/go/` (api module). |
| `proto/teleport/` | Internal — teleterm daemon, web app, VNet, multiplexer, storage, QUIC peering, relay tunneling. | `gen/proto/go/` (root module). |
| `proto/accessgraph/`, `proto/prehog/` | External-facing streams: access graph + usage telemetry. | `gen/proto/go/{accessgraph,prehog}/`. |

**Naming convention.** Every modern proto declares `package teleport.<service>.<version>;` (e.g. `teleport.notifications.v1`). Service names are PascalCase, version is `v1` / `v1alpha`. Each resource has two files: `<resource>.proto` (messages, including the `<Resource>V1` type) and `<resource>_service.proto` (the gRPC service). All set `option go_package = "github.com/gravitational/teleport/api/gen/proto/go/teleport/<svc>/v1;<svc>v1";`.

**The `legacy/` split.** `api/proto/teleport/legacy/` holds the pre-v1 protos — flat `package proto;` declarations using gogoproto extensions:

- `legacy/client/proto/authservice.proto` — the **monolithic `AuthService`** (~274 RPCs — still active, gradually being decomposed into v1 services).
- `legacy/client/proto/proxyservice.proto` — `ProxyService` for proxy-to-proxy DialNode.
- `legacy/client/proto/joinservice.proto` — `JoinService` (also runs on proxy).
- `legacy/types/types.proto` — `*V1`/`*V2` resource definitions (`UserV2`, `RoleV6`, `ServerV2`, …).
- `legacy/types/events/events.proto` — every audit event type.
- `legacy/types/{metadata,mfa_device,webauthn,wrappers,trusted_device_requirement,device,resources}.proto`.

`buf.yaml` excludes the legacy tree from modern lint rules (lines 27–36); legacy is generated by `protoc-gen-gogofast` (`buf-gogo.gen.yaml`); modern by `protoc-gen-go` (`buf-go.gen.yaml`); TypeScript bindings by `buf-ts.gen.yaml`; the prehog ConnectRPC client by `buf-connect-go.gen.yaml`.

## 5. gRPC — Cross-Cutting Conventions

- **Pagination.** List methods accept `page_size` + `page_token`; return `next_page_token`. Enforced by the custom buf lint plugin (`build.assets/tooling/cmd/buf-plugin-linters/`) implementing RFD-0153's `PAGINATION_REQUIRED` rule.
- **Filtering.** List methods commonly accept a `filter` field carrying a sub-message of filter predicates. Resource-specific.
- **Status codes.** Errors are mapped from `gravitational/trace` codes to gRPC status codes by interceptors. `trace.NotFound` → `codes.NotFound`, `trace.AccessDenied` → `codes.PermissionDenied`, `trace.BadParameter` → `codes.InvalidArgument`, etc.
- **Auth.** Every gRPC method runs through a single auth interceptor that extracts identity from `tls.ConnectionState.PeerCertificates[0]` via `lib/authz/middleware.go`, then runs `lib/authz/permissions.go::authorizer.Authorize` to build a `Context` with an `AccessChecker`. Resource handlers call `Context.CheckAccessToKind`, etc.
- **Streaming.** Several services expose server-streaming RPCs — notably audit log streaming, access-request watcher, notification stream, accessgraph stream.

## 6. HTTP REST — Topology

The HTTP+WebSocket API consumed by the browser UI lives in `lib/web/`. It is registered programmatically on an embedded `httprouter.Router` in `lib/web/apiserver.go`. Routes count **~220** (see [`findings/backend-api-surface.md` §5](./findings/backend-api-surface.md) for the full breakdown).

A `/v1` prefix shim transparently strips the version, so `/v1/webapi/sessions` and `/webapi/sessions` are the same endpoint.

### 6a. Major route groups

| Prefix | Purpose |
| --- | --- |
| `/v1/webapi/login`, `/v1/webapi/passwordless/login`, `/v1/webapi/sso` | Browser login flows (local, passwordless, SSO callback) |
| `/v1/webapi/sessions`, `/v1/webapi/users`, `/v1/webapi/account` | Session + user mgmt |
| `/v1/webapi/mfa/*` | MFA registration, challenges, deletion |
| `/v1/webapi/sites/{site}/...` | Trusted-cluster aware sub-routes (one set per known cluster) |
| `/v1/webapi/sites/{site}/sessions`, `/v1/webapi/sites/{site}/connections` | Active sessions + recordings |
| `/v1/webapi/sites/{site}/sshhosts`, `/v1/webapi/sites/{site}/kube`, `/v1/webapi/sites/{site}/apps`, `/v1/webapi/sites/{site}/databases`, `/v1/webapi/sites/{site}/desktops`, `/v1/webapi/sites/{site}/git_servers`, `/v1/webapi/sites/{site}/mcp_servers` | Resource listing per kind |
| `/v1/webapi/sites/{site}/roles`, `/users`, `/tokens`, `/integrations`, `/joinTokens` | Cluster config |
| `/v1/webapi/sites/{site}/accessrequest/*`, `/notifications/*`, `/locks/*` | Identity Governance |
| `/v1/webapi/sites/{site}/devicetrust/*`, `/spiffe/*`, `/workloadidentity/*` | Identity Security + MWI |
| `/v1/webapi/sites/{site}/discovery/*`, `/usertasks/*`, `/secreports/*`, `/accessgraph/*` | Identity Security workflows |
| `/v1/scripts`, `/v1/scripts/node-join/install.sh` | Node-join installer (text-template rendered) |
| `/.well-known/jwks.json` | JWKS used by App Access JWTs |
| `/v1/teleport-auth` | Internal proxy-to-auth coordination |

### 6b. Middleware wrappers

Each route handler is wrapped by zero or more:

- `WithAuth(handler)` — requires a logged-in web session, sets up the user context.
- `WithClusterAuth(handler)` — also resolves the `{site}` parameter to a remote cluster.
- `WithClusterAuthWebSocket(handler)` — same, for upgrade-to-WS endpoints.
- `WithLimiter(handler)` — rate-limited via `lib/limiter`.
- `WithCSRF`, `WithErrorMapping`, … (`lib/httplib/*.go`).

### 6c. WebSockets

| Endpoint | Library | Purpose |
| --- | --- | --- |
| `/v1/webapi/sites/{site}/.../connect/ws` (SSH terminal, kube exec) | **gorilla/websocket** via `lib/web/terminal/terminal.go` | Live SSH / kube exec terminal traffic, length-prefixed protobuf frames |
| `/v1/webapi/sites/{site}/desktops/.../connect` | gorilla/websocket | Live RDP via TDP (Teleport Desktop Protocol) |
| `/v1/webapi/sites/{site}/sessions/.../events/ws`, `…/playback/ws` | gorilla/websocket | Session-recording playback streaming |
| `/webapi/connect/ws` (ALPN upgrade) | **gobwas/ws** via `lib/web/conn_upgrade.go` | Connection upgrade for clients behind HTTP/1.1-only load balancers |

## 7. Code Generation

Triggered by `make grpc` (which runs `build.assets/genproto.sh`):

```
*.proto  →  buf  →  protoc-gen-go     →  gen/proto/go/  (modern)
                  →  protoc-gen-gogofast →  gen/proto/go/ (legacy)
                  →  protoc-gen-connect-go →  gen/proto/go/prehog/ (prehog only)
                  →  protoc-gen-ts        →  web/packages/.../  (TS)
```

Configs: `buf.yaml`, `buf.lock`, `buf-go.gen.yaml`, `buf-gogo.gen.yaml`, `buf-connect-go.gen.yaml`, `buf-ts.gen.yaml`, `buf-legacy.yaml`. Custom lint plugin: `build.assets/tooling/cmd/buf-plugin-linters/`.
